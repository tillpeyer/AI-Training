Generated by the `elcai-update-bmad` skill on 2026-08-25.
ELCAi version whose overrides were checked: **1.0.0** (pins BMAD `@6.10.0` in `src/commands/version.js:21`).

> **Scope caveat.** This run was executed from the **AI-Training** repo, not an `elcai-method`
> checkout, so `elcai/agent_customize/*.toml` and `elcai/workflow_customize/*.toml` were read from

> Content is identical to the published release; it just isn't editable in place.

## Bottom line

**Mechanically clean, semantically expensive.** BMAD's quick-update leaves **zero** leftover files
and **zero** missing files — there is no cleanup bug to fix in `src/commands/update.js`, and no new
`isVersionBelow` gate is needed. `src/utils/paths.js` needs no changes either.

The cost is entirely in ELCAi's own override surface: **1 override is outright orphaned** and
**8 more target newly-deprecated skills**, because 6.11.0 is a consolidation release that collapses
many single-purpose skills into a few multi-intent ones.

No menu-code collisions were found.

32 directories removed, 76 added between the two clean installs. Both counts are inflated by
artifacts of the diff method itself — `/tmp/…/old`, `/tmp/…/new`, `docs`, `_bmad-output/planning-artifacts`,
`_bmad-output/implementation-artifacts` — and by the fact that every skill directory appears **twice**,
once under `.claude/skills/` (claude-code) and once under `.agents/skills/` (github-copilot).

**Genuinely new top-level BMAD directories (3):**

| Directory | Note |
|---|---|

| `_bmad/core/v6-shims` | New in 6.11.0 |

`src/utils/paths.js` only ever names `_bmad`, `_bmad/_config`, `_bmad/custom`, `_bmad/elcai`,
`.claude/skills`, and `.github/skills`. All three new directories are additive and sit outside those
constants, so **no `paths.js` change is required**. `src/utils/bmad-manifest.js` reads
`_bmad/_config/manifest.yaml`, whose location and shape are unchanged.

Removed sub-directories are all consequences of §1/§2 consolidation, e.g.
`bmad-document-project/{templates,workflows}`, `bmad-market-research/steps`,
`bmad-domain-research/domain-steps`, `bmad-technical-research/technical-steps`,
`bmad-generate-project-context/steps`, `bmad-review-edge-case-hunter/references`,
`bmad-brainstorming/analysis`.

**Packaging wart (BMAD's, not ELCAi's):** the 6.11.0 install tree contains `__pycache__`
directories — `bmad-retrospective/scripts/__pycache__`, `bmad-retrospective/scripts/tests/__pycache__`,
`bmad-sprint-planning/scripts/__pycache__`, `bmad-sprint-planning/scripts/tests/__pycache__`.
Compiled bytecode is being shipped or generated at install time. Harmless, but it is churn in any
repo that tracks `.claude/skills/` (AI-Training does, for the story-loop allowlist) and worth an
upstream note.

## Recommendations (not applied)

Nothing is broken while the pin stays at 6.10.0. The following are the prerequisites for moving it:

1. **Resolve the orphan first (blocking).** Decide what happens to
   `elcai/workflow_customize/bmad-check-implementation-readiness.toml` — merge its `persistent_facts`
   into the existing `bmad-sprint-planning.toml`, or drop them. This is the only finding that
   silently loses behavior on upgrade.
2. **Plan the four many-to-one merges** from §2 before bumping, not after:
   `{create-story, dev-story, quick-dev}` → `bmad-build`;
   `{market, domain, technical}-research` → `bmad-deep-recon`;
   `document-project` → `bmad-project-context`; `sprint-status` → `bmad-sprint-planning`.
3. **Update `elcai/README.md`'s Skills table** in the same pass — every row naming one of the nine
   affected skills, in particular the `bmad-sprint-status ← Dev (Amelia) [SPS]` row.
4. **Consider a native-`BD` decision for `bmad-agent-dev`.** BMAD now offers one code for what was
   three; check whether any ELCAi guidance still tells users to run `DS`/`QD`/`CS`.
5. **Fix this skill's own `SKILL.md`** step 3b table (five files → six; `bmad-agent-pm` does define
   menu items). See §3.
6. **No `src/commands/update.js` change, no `src/utils/paths.js` change.** Explicitly out of scope
   for this bump.
