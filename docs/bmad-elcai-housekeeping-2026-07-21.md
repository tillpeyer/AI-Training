# BMAD/ELCAi housekeeping — findings & improvement points (2026-07-21)

Findings from a skills/hooks/version audit of this repo's BMAD + ELCAi install. Fixed items are marked done; the rest are open for upstream or a future pass.

## Fixed this session

- [x] `.agents/` (BMAD's per-IDE output for `github-copilot`, ~900 files) was untracked and unignored — `git add .` would have staged it. Added to `.gitignore`.
- [x] `.github/{agents,prompts,skills}` (ELCAi's separate `github-copilot` output path, distinct from `.agents/`) had the same problem. Added `.github/` to `.gitignore`.
- [x] `CLAUDE.md`'s "Things you should NOT do" section documented a stale story-loop layout (`.claude/commands/bmad-bmm-story-loop.md`, a `_bmad/bmm/workflows/...` workflow) that no longer exists — the loop is a skill now (`.claude/skills/bmad-elcai-story-loop/**`). Corrected.
- [x] `CLAUDE.md`'s agent role table pointed at slash commands (`/bmad-agent-bmm-sm`, `/bmad-agent-bmm-dev`, `/auditor`) that are mostly dead. Rewrote to reflect current skill-based invocation.
- [x] Deleted 8 stale command files from `.claude/commands/`: `bmad-agent-bmm-{analyst,architect,dev,pm,tech-writer,ux-designer}.md` and `bmad-agent-elcai-auditor.md` (superseded by self-contained skills), and `bmad-agent-bmm-sm.md` (Scrum Master role deprecated outright — `bmad-create-story` now owns story prep).
- [x] Added a local (gitignored) `PreToolUse` hook (`.claude/hooks/git-safety-guard.ps1`) that blocks `gh pr merge`, `git push --force`/`-f`, direct pushes to `main`/`master`, and `git add` of BMAD installer output.
- [x] Reconciled BMAD/ELCAi version policy: BMAD pinned to stable (`6.10.0`), ELCAi pinned to unstable/alpha (`0.11.1-alpha.3`) in this training repo specifically — see memory `bmad-version-policy`.
- [x] Moved `install-story-loop` from `.claude/commands/` (explicit-invoke only) to `.claude/skills/install-story-loop/SKILL.md` (autonomously invokable). Its description was already written as a skill-style trigger (`"Use when the user says..."`), which is inert text on a command — Claude never reads command descriptions to decide relevance, only explicit `/name` invokes them. Updated the skill's own self-copy step (it propagates itself into other projects), the `.gitignore` allowlist, `CLAUDE.md`, and the drift-guard hook's regex accordingly. The other 3 remaining commands (`bmad-master`, `qa`, `quick-flow-solo-dev`) have bare non-trigger descriptions — correctly placed as explicit-only, no change needed.
- [x] Added two new **commands** (explicit-invoke, correctly bare-description): `.claude/commands/elcai-check-env.md` (portable — MCP server config diff, hook wiring, BMAD/ELCAi version drift) and `.claude/commands/check-training-env.md` (this repo's own policy layered on top: workshop MCP servers, stable-BMAD/unstable-ELCAi split, story-loop presence, safety-hook wiring, gitignore coverage). Both tested step-by-step against the live repo — all checks passed. Currently local-only (gitignored); shipping decision still open (see below).
- [x] **Found and fixed a real bug**: `_bmad/config.toml` had no `[modules.elcai]` section at all — BMAD's installer can't parse `_bmad/elcai/module.yaml` (the same lookup failure behind the "could not locate module.yaml for 'elcai'" warning noted earlier), so ELCAi's Jira/Confluence config answers were never captured. The `sprint-summary` workflow (which the auditor/Amelie skill uses, per CLAUDE.md's Block 3 demo) expects `{jira_project_key}`/`{confluence_project_space}` to resolve from module config — with no `[modules.elcai]` section, they had nothing to resolve against. Fixed by adding `[modules.elcai]` to `_bmad/custom/config.toml` (team-committed override file, never touched by the installer) with the one confirmed real value (`jira_project_key = "RHBGAF"`, matching `.mcp.json`) and the project's own declared local-only Confluence convention (`confluence_project_space`/`confluence_technical_space = "LOCAL-ONLY"`, matching `_bmad-output/planning-artifacts/prd.md`'s `confluenceSpaceKey: "LOCAL-ONLY"`). `jira_board_id`, `bitbucket_workspace`, `bitbucket_repository` left unset — no real values exist for this repo (GitHub, not Bitbucket; no live board configured) and fabricating them would be worse than leaving them empty. Verified end-to-end with `python3 _bmad/scripts/resolve_config.py --project-root . --key modules.elcai` — now returns the real values. Added as check-training-env step 8 so it's caught if it regresses.

- [x] **Found and fixed a real merge regression**: merging `main` back into `feature/elcai-housekeeping-config-fixes` before the PR merged (commit `15da813`) silently reverted large parts of the just-shipped `.gitignore` and `CLAUDE.md` fixes back to their pre-fix state — because `main` at that point still carried `feature/story-1-8-admin-delete-menu-item`'s **older** commits (`cc9e279`/`f5d9cdb`), which predated yesterday's corrections and still had the stale `.claude/commands/install-story-loop.md` allowlist and blanket `_bmad/` gitignore. The merge's conflict resolution picked `main`'s side for those hunks. Net effect after PR #19 merged: `.gitignore` lost the `.agents/`/`.github/` ignores and the granular `_bmad/*`/`.claude/skills/install-story-loop/` allowlist, reverting to blanket `_bmad/` and the old `.claude/commands/install-story-loop.md` allowlist — and `CLAUDE.md`'s "Things you should NOT do" exceptions list reverted to the pre-migration story-loop-as-command description, contradicting its own agent-role table earlier in the same file. Concretely this meant **both** the stale command file and the new skill file were tracked on `main` simultaneously.
  - Caught by re-auditing `main` after the merge rather than trusting the PR diff alone — worth remembering that a "merge branch main into feature" step done mid-flight on a long-lived feature branch can silently re-introduce fixed content if the target branch still has stale intermediate commits.
  - Fixed via a follow-up branch `fix/restore-elcai-gitignore-claude-md` (PR #20, merged): restored the granular `.gitignore` allowlist pattern, restored `CLAUDE.md`'s exceptions list, and deleted the now-duplicate `.claude/commands/install-story-loop.md` (superseded by `.claude/skills/install-story-loop/SKILL.md`).
  - Verified post-merge on a fresh `git pull` of `main`: `.gitignore` has `_bmad/*` (not blanket `_bmad/`), no reference to `.claude/commands/install-story-loop.md` remains anywhere, and `CLAUDE.md`'s exceptions list matches the skill-based layout.
