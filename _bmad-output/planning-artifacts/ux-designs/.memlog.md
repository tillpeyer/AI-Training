- (decision) Named aesthetic ratified from styles.css: editorial print-menu. Warm paper ground, near-black ink, one vermillion accent, dotted leaders running name-to-price, deliberately square corners. Sourced from the spike's restyle commit 6aadae6.
- (decision) Colour tokens ratified verbatim from styles.css :root - paper #f5f2eb, paper-deep #ebe6db, ink #16120f, ink-soft #5c5248, rule #ddd6c8, rule-strong #bcb2a0, accent #b1341c, accent-soft #f0d9c8, ok #2f6b3d.
- (decision) Typography ratified: display family Palatino Linotype / Book Antiqua / Palatino / Iowan Old Style / Georgia serif; body family Candara / Optima / Gill Sans / Segoe UI sans. NO WEB FONTS - deliberately OS-shipped families so the frontend adds no font dependency and no network request. This is a hard rule, not a default.
- (decision) Shape rule ratified: border-radius 0 everywhere. The square corner is the aesthetic, echoing a printed menu sheet rather than a web app.
- (decision) Focus treatment ratified: one app-wide :focus-visible of 2px solid accent at 2px offset, meeting WCAG AA. Defined once in styles.css; no component overrides it.
- (decision) Container ratified: max-width 40rem, centred, single column. Sole breakpoint at 34rem. No multi-column layout at any width - the print-sheet metaphor is a single measure.
- (decision) Motion ratified: staggered rise-in on menu rows (0.5s, cubic-bezier(0.2,0.7,0.3,1), 40-280ms delays capped at the 6th row) and a 0.18s button hover lift. prefers-reduced-motion disables both, in every file that animates.
- (constraint) AUDIT FINDING - the design system reaches only the shell and one of three routes. var(--token) vs hard-coded hex counts: app.css 14/0, menu-page.css 25/0, my-orders-page.css 0/2, admin-page.css 0/2, error-banner inline styles 0/3. /orders, /admin and the shared ErrorBanner bypass the token system entirely.
- (constraint) AUDIT FINDING - four off-palette values in live use. #a4262c error red (error-banner, admin field-error) where the accent is #b1341c; #fdf3f4 error background with no token at all; #107c10 confirmation green (my-orders, admin) where --ok is #2f6b3d; #e5e5e5 table rule (my-orders) where --rule is #ddd6c8.
- (constraint) AUDIT FINDING - ErrorBanner violates the shape rule with border-radius 4px in a system that is square everywhere else, and hard-codes all three of its colours inline rather than referencing tokens.
- (constraint) AUDIT FINDING - the .confirmation pattern has two different visual treatments depending on route. menu-page.css gives it a 3px accent-left border plus var(--ok) text; my-orders-page.css and admin-page.css give it bare #107c10 text with no border. Same semantic component, two appearances.
- (decision) Resolution for all four audit findings: the token system is the single source of truth. Every colour, rule and radius in every route and shared component resolves through var(--token). No component may hard-code a hex. ErrorBanner gets --accent, an accent-soft-derived ground, and radius 0. .confirmation gets one treatment - the menu-page one, with the accent-left border - applied everywhere.
- (decision) Two error tokens added to close a real gap: the palette had no error ground and no error ink distinct from the accent. Rather than inventing new hues, error state reuses --accent for ink and --accent-soft for ground, which is why #a4262c and #fdf3f4 can be deleted outright rather than tokenised.
- (decision) State vocabulary ratified from my-orders-page.html, which is the most complete: not-signed-in, loading, load-error, empty, populated, per-row-pending, mutation-error, confirmed. Eight states, all already implemented on /orders. This becomes the required state set for every data-backed surface.
- (constraint) State coverage is uneven. /orders implements all eight states. / (menu) has loading and error but no empty state. /admin has no loading state for the menu it does not read, and its confirmation and error are present. Levelling this is EXPERIENCE.md's job.
- (decision) Accessibility floor ratified from what the code already does - role=alert on error banner and field errors, role=status on confirmations, aria-invalid plus aria-describedby on admin fields, nav aria-label=Main, visually-hidden table caption, aria-hidden on the decorative dotted leader, th scope=col, one WCAG AA focus ring, prefers-reduced-motion honoured. This is the floor, not the ceiling; new surfaces inherit all of it.
- (constraint) Accessibility inconsistency: /admin gives per-field error messages with aria-invalid and aria-describedby wiring, while / (menu) surfaces form errors only through the shared banner with no per-field association. The admin pattern is the better one and should be the standard.
- (decision) Voice and tone ratified from existing microcopy - lower-case sentence fragments, no exclamation, no personality. Order submitted. / Order cancelled. / You have no orders yet. / Loading orders... Uppercase letterspaced small caps are reserved for labels and buttons, never for body copy or messages.

- (event) All five [ASSUMPTION] tags resolved by the user 2026-09-03. Two reversed the proposal: dark mode is required (not light-only) and Cancel needs a confirm step (not left unguarded). Both spines moved to status:final.
- (decision) RESOLVED 1 - the menu route empty state copy is "No dishes on the menu today." Proposal accepted. Folded into AC 2.1.3, which already had open work.
- (override) RESOLVED 2 - DARK MODE IS REQUIRED. This reverses the earlier decision to declare the palette light-only. Nine dark tokens designed: paper-dark #1c1714, paper-deep-dark #13100e, ink-dark #f0ebe1, ink-soft-dark #a89c8d, rule-dark #332b25, rule-strong-dark #4d4238, accent-dark #e8674a, accent-soft-dark #3a1f17, ok-dark #6bbf7f. Deliberately NOT an inversion - the ground is a warm brown-black so the paper metaphor survives as unlit paper, and paper-deep stays darker than the sheet to preserve the tonal relationship rather than flipping it.
- (decision) The accent had to be LIFTED for dark, from #b1341c to #e8674a: #b1341c on #1c1714 fails WCAG AA. This is the one token whose hue genuinely changes between themes rather than just its lightness.
- (decision) Two non-colour changes fall out of dark mode: the canvas grain lightens instead of darkening (rgba(240,235,225,0.02) rather than rgba(22,18,15,0.014)), and the sheet drop shadow is dropped entirely because against a dark ground it reads as a black smear. Depth in dark comes from the paper/paper-deep tonal step alone. Do not deepen the shadow to compensate.
- (decision) Dark mode is implemented by redefining the same custom properties inside prefers-color-scheme, so components stay theme-blind. No in-app toggle: a toggle needs persisted state, a shell control and a first-load decision, none of which this tool earns.
- (constraint) AC 2.1.15 (dark mode) is BLOCKED BY AC 2.1.14 (token audit). A hard-coded hex looks correct in light and breaks in dark, so the two off-palette route stylesheets and ErrorBanner must be tokenised before the theme can work at all. Recorded as blockedBy in the context file.
- (assumption) The dark contrast ratios are COMPUTED, not measured with a tool. accent-dark on accent-soft-dark is the tightest pair at roughly 4.5:1. Flagged in both spines and in AC 2.1.15: verify with a checker before ticking, and if it measures below AA, lighten accent-dark rather than darkening the ground, which would break the error banner border.
- (decision) RESOLVED 3 - per-field error association added to the order form. The /admin signal-forms implementation already does it correctly and becomes the standard: aria-invalid bound to touched-and-invalid, aria-describedby pointing at its own message element, message element reserving min-height so validation never shifts layout. Folded into AC 2.1.4 as additional required work and recorded as policy P18.
- (override) RESOLVED 4 - CANCEL NEEDS A CONFIRM. This reverses both the earlier proposal to leave it unguarded AND the "no confirmation dialogues anywhere" interaction primitive, which had to be rewritten rather than patched.
- (decision) The confirm is INLINE AND ON THE ROW, not a modal. A modal would be the only modal in the application and would drag in a focus trap, escape handling, scroll locking, a backdrop, and a visual language of rounded corners and elevation that DESIGN.md explicitly rules out. The inline form keeps the decision on the object it affects and needs no new machinery.
- (decision) Arming mechanics: click Cancel arms the row (3px accent left border, accent-soft ground, cell swaps to "Cancel order" plus "Keep"); focus moves to the confirm; Escape and Keep both disarm; arming another row disarms the first, so exactly one row is armed at a time; nothing is sent until the confirm.
- (decision) A new ninth state, "armed", was added to the state vocabulary, which had eight. It sits between populated and row-pending.
- (decision) Two accessibility requirements are specific to the confirm pattern. The confirm button accessible name must identify the ROW and not just the verb - aria-label="Cancel order of Risotto aux champignons" - because "Cancel order" alone is ambiguous in a table and a screen-reader user tabbing in has no visual row context. And arming is announced through a POLITE live region, never role=alert, because arming is not an error. Keep is the safe default wherever focus or Enter handling could be ambiguous.
- (decision) The confirm step reduces the double-cancel path but does NOT replace the backend guard: a double confirm still returns 409 ALREADY_CANCELLED and the banner shows the backend message verbatim. Recorded in flow 2 as the variant that proves the design.

Nadia and Marc are #3 On-site Employees; Priya is #2 Canteen Admin / Kitchen Lead. Names are illustrative, roles are binding.
